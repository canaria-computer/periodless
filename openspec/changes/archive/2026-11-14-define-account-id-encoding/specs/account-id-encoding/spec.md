# Spec Delta

## Purpose

日商簿記3級範囲の勘定科目を64bit符号なし整数（`u64`）として一意に識別し、上位ビットによる勘定区分判定と16bit流動性スコアによる流動性配列順ソートを可能にするIDエンコーディング仕様を定義する。

## ADDED Requirements

### Requirement: 64bit整数による勘定科目IDのビットレイアウト

勘定科目IDは64bit符号なし整数（`u64`）として表現し、以下のビットレイアウト（0-indexed
LSB基準でワード境界に揃えた `0xC000_LLLL_BBBB_0000`
形式）を持たなければならない（SHALL）。なお、このビット割当および各科目のID値は設計途上の定義であり、将来変更される可能性があることをドキュメント上に明記しなければならない（SHALL）。

- **bit 63..=60（4bit / `<< 60`）**: 勘定区分（Category）
  - `0001` (`0x1`): 資産
  - `0010` (`0x2`): 負債
  - `0011` (`0x3`): 純資産
  - `0100` (`0x4`): 費用
  - `0101` (`0x5`): 収益
  - `0110` (`0x6`): 評価勘定科目（控除科目・特殊勘定）
- **bit 59..=48（12bit / `<< 48`）**: 将来予約（Reserved 1）とし、すべて
  `0`（`0x000`）とする
- **bit 47..=32（16bit / `<< 32`）**: 流動性スコア（Liquidity
  Score、流動性配列法に基づく降順ソート用スコア）
- **bit 31..=16（16bit / `<< 16`）**: 基底勘定科目番号（Base Account
  Number、勘定科目を一意に識別する番号）
- **bit 15..=0（16bit / `<< 0`）**: 将来予約（Reserved 2）とし、すべて
  `0`（`0x0000`）とする

#### Scenario: 勘定科目IDからの勘定区分および基底勘定科目番号の抽出

- **WHEN** 任意の勘定科目IDの bit 63..=60（`id >> 60`）および bit
  31..=16（`(id >> 16) & 0xFFFF`）を参照する場合
- **THEN** bit 63..=60 から `0b0001`〜`0b0110` の勘定区分コードが得られ、bit
  31..=16 から基底勘定科目番号が得られる

#### Scenario: 将来予約ビットのゼロ保持

- **WHEN** 定義された勘定科目IDの将来予約ビット領域（bit 59..=48 および bit
  15..=0）を参照する場合
- **THEN** すべての予約ビットが `0` となっている

### Requirement: 16bit空間における流動性スコアの割り当て

流動性スコア領域（bit 47..=32 の16bit空間:
`0x0000`〜`0xFFFF`）は、流動性配列法における降順ソートを想定して以下の基準で割り当てなければならない（SHALL）。

- `0xFFFF`: 最大超流動性（現金など、最も流動性が高い科目）
- `0x0001`: 無形固定資産（流動性を持つ科目のうち最小流動性の基準値）
- `0x0000`: 該当なし（流動性の概念を持たない純資産・費用・収益・評価勘定科目）

資産および負債の各勘定科目には、流動性の高い順（流動資産・流動負債から固定資産・固定負債へ）に降順となる
`0xFFFF`〜`0x0001` の範囲のスコアを割り当てなければならない（SHALL）。

#### Scenario: 資産・負債科目の流動性降順ソート

- **WHEN**
  同一区分（資産または負債）の勘定科目を流動性スコアの降順（またはIDの降順）に並べ替える場合
- **THEN**
  現金・預金、売上債権・仕入債務、棚卸資産、その他の流動項目、有形固定資産、投資その他の資産の順に流動性配列法に沿って整列される

#### Scenario: 流動性概念を持たない区分のスコア

- **WHEN**
  純資産（`0011`）、費用（`0100`）、収益（`0101`）、評価勘定科目（`0110`）の流動性スコア領域（bit
  47..=32）を参照する場合
- **THEN** いずれも `0x0000`（該当なし）が設定されている

### Requirement: 評価勘定科目（0110）の定義と区分整理

上位4ビット
`0110`（評価勘定科目）には、「貸倒引当金」「減価償却累計額」「現金過不足」「損益」を割り当て、流動性スコア（bit
47..=32）は `0x0000`、基底勘定科目番号（bit
31..=16）に固有番号を付与しなければならない（SHALL）。また、「法人税、住民税及び事業税（法人税等）」および「雑損」は費用（`0100`）、「雑益」は収益（`0101`）としてIDを割り当てなければならない（SHALL）。

#### Scenario: 評価勘定科目のID構成の確認

- **WHEN**
  貸倒引当金、減価償却累計額、現金過不足、損益の勘定科目IDを参照する場合
- **THEN** bit 63..=60 が `0110`（`0x6`）、bit 47..=32 が `0x0000`、bit 31..=16
  が各科目の基底勘定科目番号、bit 15..=0 が `0x0000`
  で構成された一意な64bit整数値を持つ

### Requirement: YAML形式による勘定科目IDとビット内訳のドキュメント化

すべての勘定科目の64bit ID定義（16進表記、bit 63..=60 勘定区分コード、bit
47..=32 流動性スコア、bit 31..=16 基底勘定科目番号、日本語科目名、英語識別子）を
YAML
形式（`docs/勘定科目一覧/accounts.yaml`）および解説ドキュメントとして提供しなければならない（SHALL）。

#### Scenario: YAMLドキュメントからの勘定科目ID参照

- **WHEN** 開発者またはLLMが `docs/勘定科目一覧/accounts.yaml` を参照する場合
- **THEN** 全勘定科目の64bit
  ID値とそのビット構成（勘定区分・流動性スコア・基底勘定科目番号）および日英識別子を機械可読かつ人間可読な形式で取得できる
