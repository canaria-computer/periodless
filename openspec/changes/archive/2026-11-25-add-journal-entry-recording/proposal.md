# Proposal

## Why

Issue
#4「仕訳を入力できる」に対応し、複式簿記の中核である仕訳をドメインコア上に不変なレコードとして記録できるようにするため。ハッシュチェーンで連結された追記専用の仕訳履歴は、総勘定元帳・試算表・財務諸表といった導出ビューすべての前提となる権威あるデータであり、`crates/periodless-core`
は現在スタブのままなので、最初の実ドメイン実装として構築する。同時に、構文上は妥当でも実務上支障になる仕訳記述（自己取引、同一科目の重複、合計ゼロなど）を、記録前に「違反」と「警告」に区分して検証できる必要がある。

## What Changes

- `crates/periodless-core` に仕訳の記録機能を実装する:
  - **仕訳レコードの構成要素**:
    取引日時・コミット日時・借方明細列（勘定科目ID＋金額）・貸方明細列（勘定科目ID＋金額）・前レコードのハッシュ値（初期値は32バイトのゼロ）・適用通信欄（任意の
    UTF-8
    文章）。附随情報は仕様未確定のため本変更では含めず、将来の変更で追加する。
  - **金額の単位**:
    金額は**1銭単位（0.01円）の整数**で保持する。割合計算（百分率・按分など）に伴う丸め誤差を避けるためであり、浮動小数点は使用しない。内部表現は
    i64 とする。
  - **日時**: hifitime を `TransactionAt` / `CommittedAt` の Newtype
    で包み、構築時にミリ秒境界への切り上げ正規化を適用して正規化済み瞬間を保持する。正準文字列表現は
    `YYYYMMDDTHHMMSS.sssZ`（UTC・小数部3桁・うるう秒の SS=60 を許容）。
  - **ハッシュチェーン**: 各レコードのハッシュを
    BLAKE3（32バイト）で計算し、前レコードのハッシュを preimage
    に含めて連結する。preimage
    は固定接頭辞（ドメイン分離＋バージョン識別）を伴う決定的なバイト列表現とする。
  - **台帳 `Ledger`**:
    インメモリ・追記専用。追記時にコミット日時の単調性（直近レコードと比較して等しいか増加であること。過去への記録は拒否）と前レコードハッシュの一致を検証する。チェーン全体のハッシュ再計算による改変検出を提供する。
  - **不変条件の強制**: 貸借一致（不一致は `Result::Err`
    で拒否）・金額非負・勘定科目IDの妥当性（`account-id-encoding`
    仕様に従う検証）。
  - **Functional Core**:
    システムは時計を持たない。取引日時・コミット日時はすべて入力として与えられる。取引日時は過去の日時を記録できる。
  - **明細順序の正規化と取引の同一性**:
    coreの仕訳レコードは構築時に借方・貸方の各明細列を独立に「金額（降順）→
    勘定科目ID（降順）」の安定ソートで正規化して保持する。等価性（`PartialEq` /
    `Eq`）とハッシュ（`Hash`）は正規形に基づき、側内の順序のみが異なる仕訳は同一の取引とみなす。同じ行の左右の対応（組）は正規形に含めない。BLAKE3レコードハッシュの
    preimage の明細列も正規化順で構成する。
- **仕訳の検証仕様を新設する**（`journal-entry-validation`）:
  構文上セーフでも実務上支障になる記述を、**違反（記録を拒否）**と**警告（記録を受理して通知）**に区分して検証する。ルールは以下の11つ:
  - 違反:
    1. 省略行（片側のみのレコード行）の前に、両側の明細を持つ行が少なくとも1件存在しない
    2. 借方・貸方のそれぞれの中で同一の勘定科目が2回出現する（左右両方への出現は違反ではない）
    3. 借方と貸方の明細列が勘定科目・金額・順序のすべてで一致する（自己取引）
    4. 合計金額が0である
    5. 借方合計または貸方合計が i64 の最大値を超える
    6. 金額表現に桁区切り文字（`_`・`'`・`.`・`,`）が連続して現れる
    7. 金額表現に桁区切り文字以外の印字可能ASCII文字が出現する
    8. 金額表現が基数プレフィックス表記（`0b`・`0x`・`0o`
       等）と混同される形である
  - 警告（記録は受理する）: 9. 金額の直前にある勘定科目名の末尾が数字である 10.
    合計金額が2^40円を超える（誤入力の可能性） 11.
    金額表現が0埋めされた表記である（外部インターフェースが8進数解釈する恐れ）
- `crates/periodless-journal-dsl`
  に、検証に必要な入力構造と正規化等価性を追加する:
  解析結果が行構造（各行の借方・貸方の有無）・科目名・金額表現を保持・公開し、仕訳記述の検証（省略行・科目名末尾・金額表現の連続区切り／非正準ASCII／基数プレフィックス／0埋め）を提供する。あわせて、借方・貸方の各明細列を独立に「金額（数値・降順）→
  科目名文字列長（降順）→
  科目名辞書順（降順）」の安定ソートで正規化した正規形に基づく等価性（`PartialEq`
  / `Eq` /
  `Hash`）を定義する（側内の順序のみが異なる仕訳記述は同一の取引とみなす。保持する明細の並び順は整形出力のため変更しない）。構文解析そのものは検証を行わないという既存要件の責務分担を維持する。
- 勘定科目ID `AccountId`（u64 Newtype）・金額 `Amount`（1銭単位の i64
  Newtype）・通信欄 `Memo`（非空 UTF-8）を導入する。
- 基本用語対訳表（`CONTRIBUTING.md`）へ取引日時（`TransactionAt`）・コミット日時（`CommittedAt`）・適用通信欄（`Memo`）・台帳（`Ledger`）等を追加する。

## Capabilities

### New Capabilities

- `journal-entry-recording`:
  仕訳レコードの構成要素、1銭単位での金額保持、日時のミリ秒切り上げ正規化、明細順序の正規化と取引の同一性、貸借一致の強制、コミット日時の単調性、BLAKE3
  ハッシュチェーン（preimage の明細列は正規化順）、追記専用台帳と改変検出の仕様
- `journal-entry-validation`:
  仕訳記述の意味検証（違反と警告の区分、および11の検証ルール）の仕様

### Modified Capabilities

- `account-terminology`: 基本ドメイン概念の標準対訳へ、取引日時（`TransactionAt`
  / `transaction_at`）・コミット日時（`CommittedAt` /
  `committed_at`）・適用通信欄（`Memo` / `memo`）・台帳（`Ledger` /
  `ledger`）・前レコードハッシュ（`previous_record_hash`）・レコードハッシュ（`RecordHash`
  / `record_hash`）を追加する
- `journal-entry-dsl`:
  解析結果が行構造（各行の借方・貸方の有無）を保持・公開し、記述の検証（省略行・科目名末尾の数字・金額表現ルール）と、明細順序の正規化に基づく取引の同一性（`PartialEq`
  / `Eq` / `Hash`）を提供する。構文解析と意味検証の責務分担は維持する

## Impact

- `crates/periodless-core`:
  新規実装（金額・勘定科目ID・通信欄・日時・ハッシュ・仕訳・検証・台帳の各モジュール。スタブ関数
  `add` は削除）
- `crates/periodless-journal-dsl`:
  行構造の保持・公開と記述構造検証の追加、検証型の共有のため `periodless-core`
  への依存追加
- `Cargo.toml` / `crates/periodless-core/Cargo.toml`: workspace 依存へ
  hifitime（バージョン固定）と blake3 を追加
- `CONTRIBUTING.md`: 基本用語対訳表へ新用語を追加
