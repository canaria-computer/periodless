# Design

## Context

Periodlessは紙の複式簿記（日商簿記3級範囲）をデジタル化するRust製会計コアライブラリであり、初期段階からAgentic TDDによって開発を進める（背景は `proposal.md` を参照）。
現在、`README.md` と `docs/README.md` に概念・製品要求が定義され、`docs/勘定科目一覧/` 配下の6つのMarkdownファイルに簿記3級で使用する勘定科目名が日本語で列挙されているが、具体的なコーディング規約（`CONTRIBUTING.md`）、AIエージェント向けの要約指針（`AGENTS.md`）、および勘定科目・簿記用語の英語識別子対訳が未整備である。

## Goals / Non-Goals

**Goals:**
- `CONTRIBUTING.md` に人間・AI双方が従うべき明確なRustコーディング規約・テスト規約・Git/PRルールを定義する。
- `docs/勘定科目一覧/*.md` の全勘定科目に対して、Rustの型/バリアント名（`UpperCamelCase`）と変数/関数名（`snake_case`）の標準対訳を表形式で付与し、LLMが迷わず参照できる構造にする。
- `AGENTS.md` および `openspec/config.yaml` に最重要原則と参照パスを凝縮し、AIエージェントのコンテキスト効率と規約遵守率を高める。

**Non-Goals:**
- この変更では、会計ドメインコアのRust実装（`src/` 配下のプロダクションコード）自体はまだ行わない。
- 簿記3級の範囲を超える勘定科目の追加は行わない。

## Decisions

### 1. ドキュメントの役割分担（`CONTRIBUTING.md` / `AGENTS.md` / `docs/勘定科目一覧/*.md`）
- **決定**:
  - `CONTRIBUTING.md`: コーディングルール、API設計、型設計、エラーハンドリング、Agentic TDD、基本ドメイン用語対訳、Git Commit / PR ルールの正式なリファレンスとする。
  - `docs/勘定科目一覧/*.md`: 資産・負債・純資産・収益・費用・その他（評価勘定・決算勘定）ごとの勘定科目日英対訳リファレンスとする。
  - `AGENTS.md`: AIエージェントが毎セッション最初に読み込む「厳選された行動規範＋ドキュメントマップ」とし、詳細の重複を避けて高密度に保つ。
  - `openspec/config.yaml`: `context` フィールドにプロジェクトの技術スタック・基本原則・規約を記載し、OpenSpecのアーティファクト生成時にも規約を強制する。
- **理由**: すべての勘定科目（約85科目）を `AGENTS.md` や `CONTRIBUTING.md` にベタ書きするとコンテキストを圧迫するため、基本ドメイン用語は `CONTRIBUTING.md` に置き、勘定科目の網羅的な対訳は `docs/勘定科目一覧/` に構造化して配置するのが最も参照性・保守性に優れる。

### 2. `docs/勘定科目一覧/*.md` のテーブル構造
- **決定**: 各ファイルを以下のMarkdownテーブル形式に統一する。
  - 列構成: `| 日本語科目名 | 型・バリアント名 (UpperCamelCase) | 変数・メソッド名 (snake_case) | サブ区分・備考 |`
- **理由**: LLMが `enum Account` のバリアント定義、構造体名、ビルダーメソッド名、テスト内の変数名のいずれを書く場合でも、変換ルールを推測せずにそのままコピー＆ペーストできるため。

### 3. 日本語テスト関数名とRustコンパイラ警告の扱い
- **決定**: テストコード（`#[cfg(test)]` モジュールや `tests/`）では日本語の関数名（例: `fn 貸借が不一致の仕訳は拒否される()`）を推奨・許容し、必要に応じて `#![allow(non_ascii_idents)]` または `#[allow(non_ascii_idents)]` の利用を規約に明記する（プロダクションコードの公開・内部識別子は英語に統一する）。
- **理由**: プロダクションコードのAPIはRustエコシステムとの親和性およびフルーエントなメソッドチェーンのために英語識別子としつつ、テスト関数名を日本語にすることで `docs/README.md` の受入条件とテストの1対1対応を人間・AIの双方にとって一目瞭然にするため。

## Risks / Trade-offs

- **[Risk] `AGENTS.md` と `CONTRIBUTING.md` の二重管理による乖離** → `AGENTS.md` には不変のコア原則とチェックリストのみを厳選して記載し、具体的なコード例や詳細規則は `CONTRIBUTING.md` を単一の真実の源泉（Single Source of Truth）として参照させる。
- **[Risk] 勘定科目の英語訳の揺れ（米国会計基準と日本基準のニュアンス差）** → 日商簿記3級の標準・許容勘定科目と1対1に対応する英語識別子を `docs/勘定科目一覧/*.md` で確定させ、「コード上はこのテーブルの識別子を正とする」と規約で固定する。
