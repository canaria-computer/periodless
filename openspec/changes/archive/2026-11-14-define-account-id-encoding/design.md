# Design

## Context

Periodless では日商簿記3級範囲の勘定科目を `docs/勘定科目一覧/`
で管理しているが、これまで各科目には数値IDや貸借対照表・試算表での配列順序（流動性配列法）を表すコードが定義されていなかった。
今回、64bit整数型（`u64`）を用いて「bit 63..=60: 勘定区分」「bit 59..=48:
将来予約（Reserved 1）」「bit 47..=32: 流動性スコア（降順ソート想定）」「bit
31..=16: 基底勘定科目番号（Base Account Number）」「bit 15..=0:
将来予約（Reserved
2）」を組み合わせた勘定科目ID体系を策定し、評価勘定科目を含む全勘定科目について
YAML 等でドキュメント化する（背景は `proposal.md`
を参照）。なお、このID体系は設計途中で変わる可能性があるため、その旨を明記する。

## Goals / Non-Goals

**Goals:**

- 64bit整数（`u64`）のビットレイアウトを16進数表記（`0xC000_LLLL_BBBB_0000`）でも人間・LLMが直感的に読めるワード境界に定義する。
- 評価勘定科目（`0110`）の科目範囲と流動性スコア（`0x0000`）を確定し、`その他・評価勘定.md`
  に混在していた費用・収益科目（法人税等・雑損・雑益）を適切な区分へ整理する。
- 全勘定科目の64bit ID・区分コード・流動性スコア・基底勘定科目番号・日英識別子を
  `docs/勘定科目一覧/accounts.yaml` と各 Markdown ファイルに統一的に記述する。

**Non-Goals:**

- 現時点での Rust ドメインコアへの `AccountId` 型実装（今回は仕様と YAML /
  Markdown ドキュメントの策定を対象とする）。

## Decisions

### 1. 64bit 勘定科目IDのビットレイアウト設計

- **決定**:
  64bit符号なし整数（`u64`）を以下の16進16桁（`0xC000_LLLL_BBBB_0000`）として構成する。
  ```text
  63  60 59          48 47                  32 31                  16 15                   0
  +-----+--------------+----------------------+----------------------+----------------------+
  | Cat |  Reserved 1  |   Liquidity Score    | Base Account Number  |      Reserved 2      |
  | 4b  |     12b      |         16b          |         16b          |         16b          |
  +-----+--------------+----------------------+----------------------+----------------------+
   0xC       0x000             0xLLLL                 0xBBBB                 0x0000
  ```
  - **bit 63..=60 (`<< 60`, 4bit)**: 勘定区分（Category）
    - `0b0001` (`0x1`): 資産 (`Asset`)
    - `0b0010` (`0x2`): 負債 (`Liability`)
    - `0b0011` (`0x3`): 純資産 (`Equity`)
    - `0b0100` (`0x4`): 費用 (`Expense`)
    - `0b0101` (`0x5`): 収益 (`Revenue`)
    - `0b0110` (`0x6`): 評価勘定科目 (`Valuation`)
  - **bit 59..=48 (`<< 48`, 12bit)**: 将来予約（Reserved 1、`0x000`）
  - **bit 47..=32 (`<< 32`, 16bit)**: 流動性スコア（Liquidity Score）
    - `0xFFFF`: 最大超流動性（現金）
    - `0x0001`: 無形固定資産（最小流動性の基準値）
    - `0x0000`: 該当なし（純資産・費用・収益・評価勘定科目）
  - **bit 31..=16 (`<< 16`, 16bit)**: 基底勘定科目番号（Base Account
    Number、各区分内で `0x0001` から連番）
  - **bit 15..=0 (`<< 0`, 16bit)**: 将来予約（Reserved
    2、補助科目等の将来拡張用に予約、`0x0000`）
- **理由**:
  - 16進表記した際に先頭1桁目が区分（`1`〜`6`）、5〜8桁目が流動性スコア（`FFFF`〜`0000`）、9〜12桁目が基底勘定科目番号（`0001`〜）、末尾4桁が将来予約（`0000`）となり、ビットマスクと16進ダンプの可読性が極めて高い。
  - 基底勘定科目番号を bit 31..=16 に配置することで、将来その下位（bit
    15..=0）に補助科目や枝番を割り当てた場合でも上位〜下位への階層構造（区分 →
    流動性 → 基底科目 → 補助科目）が自然に保たれる。

### 2. 流動性スコアの段階割り当て方針（資産・負債）

- **決定**:
  将来途中に科目が挿入されてもスコアを再採番しなくて済むよう、`0xFFFF`（現金）から適切な間隔（ステップ）を空けて降順に割り当てる。
  - **資産 (`0001`)**:
    - 現金 (`Cash`): `0xFFFF`
    - 預金（当座・普通・定期）: `0xFF00`〜`0xFD00`
    - 売上債権（受取手形・電子記録債権・売掛金・クレジット売掛金）:
      `0xE000`〜`0xDD00`
    - 棚卸資産（商品・貯蔵品）: `0xC000`〜`0xBF00`
    - その他の流動資産（貸付金・手形貸付金・未収入金・前払金・仮払金・立替金・従業員立替金・受取商品券・仮払法人税等・仮払消費税・前払費用・未収収益）:
      `0xA000`〜`0x9500`
    - 有形固定資産（建物・備品・車両運搬具・土地）: `0x4000`〜`0x3D00`
    - 投資その他の資産（差入保証金）: `0x2000`
    - （基準予約: 無形固定資産 = `0x0001`）
  - **負債 (`0010`)**:
    - 仕入債務（支払手形・電子記録債務・買掛金）: `0xF000`〜`0xEE00`
    - 短期借入・当座借越（当座借越・借入金・手形借入金）: `0xD000`〜`0xCE00`
    - その他の流動負債（未払金・前受金・仮受金・預り金・従業員預り金・所得税預り金・社会保険料預り金・未払配当金・未払法人税等・仮受消費税・未払消費税・未払費用・前受収益）:
      `0xB000`〜`0xA400`
  - **純資産 (`0011`) / 費用 (`0100`) / 収益 (`0101`) / 評価勘定科目 (`0110`)**:
    - すべて流動性スコア `0x0000`（該当なし）とする。

### 3. `その他・評価勘定.md` の整理と `accounts.yaml` の構成

- **決定**:
  - `docs/勘定科目一覧/accounts.yaml`
    を新設し、ビットレイアウト仕様のメタデータと全74科目の定義を YAML
    で記述する。
  - `docs/勘定科目一覧/README.md` を新設し、64bit
    IDのビット仕様図・流動性スコア基準・「設計途中で変わる可能性がある」旨の注記・YAMLスニペットを記載する。
  - 既存の `docs/勘定科目一覧/*.md` 各ファイルにも 64bit
    ID（`0x...`）と流動性スコアの列を追加し、`法人税等`・`雑損` を `費用.md`
    へ、`雑益` を `収益.md` へ移設し、`その他・評価勘定.md` は
    `0110`（貸倒引当金・減価償却累計額・現金過不足・損益）の4科目に整理する。また作業用一時ファイル
    `docs/勘定科目一覧/評価勘定科目.txt` は内容を取り込んだ上で削除する。

## Risks / Trade-offs

- **[Risk] 今後の設計進行に伴うビット位置や流動性スコアの変更** →
  ドキュメントおよびYAMLの先頭に「本ID体系は設計途上であり変更される可能性がある」旨を明記し、ハードコードではなく定義表（`accounts.yaml`）を単一の参照元とする。
