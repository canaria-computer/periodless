# Spec Delta

## ADDED Requirements

### Requirement: 整形用コミットの署名検証

自動化ワークフローが作成する整形用コミットは、GitHub上で署名検証済み（`Verified`）として扱われなければならない（SHALL）。`Require signed commits`
を要求するブランチ保護が設定された保護ブランチへ、整形用PRを取り込んだ内容がマージできない状態を生じさせてはならない（SHALL
NOT）。

#### Scenario: 整形用PRのコミットの署名状態

- **WHEN** 自動化ワークフローが整形用ブランチへ整形差分のコミットを作成した場合
- **THEN** そのコミットはGitHub上で `Verified`
  と表示され、署名検証を要求するブランチ保護の対象ブランチへ最終的にマージできる

#### Scenario: 署名を要求する保護ブランチへのマージ

- **WHEN** 作者が整形用PRを作業ブランチへ取り込み、その作業ブランチを
  `Require signed commits`
  が有効な保護ブランチ向けのPRとしてマージしようとする場合
- **THEN**
  整形用コミットを理由とした署名検証エラーでマージが拒否されることはない

## MODIFIED Requirements

### Requirement: 整形対象コミットSHAの競合確認

自動化ワークフローは、整形処理を開始した時点の元のPRのコミットSHAとheadブランチ名を記録し、整形用ブランチの公開（整形用ブランチの作成・更新およびPR作成・更新）直前に元のPRの最新
`head.sha` および `head.ref` と一致し、かつ元のPRが `open`
であることを確認しなければならない（SHALL）。いずれかが一致しない場合、または元のPRが
`open` でない場合、修正案を公開してはならない（SHALL NOT）。

#### Scenario: 整形処理中に作者が追加コミットをpushした場合

- **WHEN** 整形処理の対象としたコミットSHAと、公開直前に取得した元のPRの最新
  `head.sha` が一致しない場合
- **THEN**
  自動化ワークフローはその古いコミットに基づく修正案を公開せず処理を中断する

#### Scenario: 整形処理中に元のPRがクローズされた場合

- **WHEN** 公開直前に取得した元のPRの状態が `open` でない場合
- **THEN** 自動化ワークフローは修正案を公開せず処理を中断する

#### Scenario: 整形処理中に元のPRのheadブランチが差し替えられた場合

- **WHEN** 公開直前に取得した元のPRの `head.ref`
  が、整形処理を開始した時点のheadブランチ名と一致しない場合
- **THEN**
  自動化ワークフローは別のブランチをマージ先とする修正案を公開せず処理を中断する
